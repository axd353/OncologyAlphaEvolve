Task:
The ancestry coordinate gives the ancestral information of the given subject. It is the given subject's representation in ancestry space. Your job is to identify a subset of the training set, given as training_data, that will be used to calculate the effect size of the given target variant target_variant for the given subject. This subset is all training samples in a closed ball of radius r around the subject, treated as a point in ancestry space. The radius r is what the priority function you design must return.

Inputs:

- training_data: a PriorityTrainingData object. records is the Oracle-Train sample set normalized into strict per-subject records. variant_names contains logical variant identifiers with any dosage__ prefix stripped. variant_dosage_fields contains the exact dosage-column names aligned to variant_names.
- ancestry_coordinate: a PriorityAncestryCoordinate object for the current target subject.
- target_variant: a PriorityTargetVariant object. name is the logical variant identifier, dosage_field is the exact dosage column name used by the oracle internals, and column_index is its aligned position in training_data.variant_names.

Output:

- radius: a finite, non-negative radius r that defines the closed ball around the ancestry point a.

Its job is only to choose the radius. The priority function should inspect only these normalized objects. It should not estimate the effect size itself; it only returns the radius that the downstream effect-size calculator will use.

What makes a good choice of r:

1. The dosage data for the training samples for the target_variant must show variance. If all training samples have the same dosage for the variant, then the effect of the variant on the phenotype label cannot be discerned.

2. If the effect size of the allele varies a lot across ancestry space, it is better to consider a small r. We want training samples close to the target subject in ancestry space, for whom the effect size of the variant is likely to be similar to that of the target. However, if the effect size of the variant is stable across training samples that are far away in ancestry space, it makes sense to choose a large r so that the estimate is based on a larger number of samples.

3. The number of training samples in the ball of radius r is important. A very small number can lead to a high-variance inferred effect size. This is undesirable.

Remember that simple priority functions are usually better than ones that are overly complicated and long. Less parsimonious priority functions are less likely to generalize.

The following is only an example of radius-selection logic. Your final function must still keep the exact three-argument signature and return only the radius.

	def priority(training_data, ancestry_coordinate, target_variant) -> float:
		num_balls = 8
		radii_and_effects = effect_size_by_cumulative_radius(
			training_data,
			ancestry_coordinate,
			target_variant,
			num_balls,
		)
		if not radii_and_effects:
			return 0.0
		if len(radii_and_effects) == 1:
			return radii_and_effects[0][0]

		drop_index = max(
			range(1, len(radii_and_effects)),
			key=lambda index: abs(
				radii_and_effects[index - 1][1] - radii_and_effects[index][1]
			),
		)
		return radii_and_effects[drop_index][0]
